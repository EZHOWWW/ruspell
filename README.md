# ruspell

**Проверка орфографии и согласования русского текста.** Текст на входе —
замечания на выходе. Без сети, без LLM, без FastAPI, без DOCX: две обязательные
зависимости и опциональный слой синтаксического согласования на numpy.

> *A Russian spell and grammar checker: a dictionary layer (pymorphy3 + Norvig
> edits) plus an optional syntax-agreement layer (slovnet) that catches errors
> in words a dictionary considers perfectly valid. Text in, issues out.
> Docs are in Russian — that is the audience.*

```python
from ruspell import SpellChecker

checker = SpellChecker(vocabulary={"техрегламент", "оквэд"})

for issue in checker.check("Указанная работы выполнены согласно приказа."):
    print(issue.word, issue.category, issue.suggestions, issue.message)
# Указанная AGREEMENT ('Указанные',) Не согласовано с «работы» по признакам: Number
# приказа   AGREEMENT ('приказу',)   Предлог «согласно» требует дательный падеж, а не родительный
```

---

## Зачем

Обычная проверка орфографии сравнивает слово со словарём. Такая проверка **по
построению** не видит ошибку в существующем слове:

| Текст | Что видит словарь | Что на самом деле |
|---|---|---|
| «согласно **приказа**» | «приказа» есть в языке | предлог требует дательного падежа |
| «**Указанная** работы выполнены» | «указанная» есть в языке | определение не согласовано с вершиной |
| «**даный** документ» | здесь словарь как раз сработает | обычная опечатка |

В деловом тексте ошибок первого типа больше, чем опечаток: текст пишут и правят
частями, и рассогласование остаётся именно там, где правку не довели до конца.
Поэтому в `ruspell` два слоя:

1. **словарный** — слова, которых нет в языке (`pymorphy3` + правки Норвига);
2. **согласование** — ошибки в существующих словах по дугам синтаксического
   дерева (`slovnet`: разбор на numpy, без torch и без JVM).

Подход мерился на внутреннем корпусе реальных писем: добавление слоя
согласования подняло F₀.₅ с 0.052 до 0.160 и снизило ложные срабатывания с 2.39
до 1.10 на 1000 токенов. Отсюда два решения, которые видно в API: доменную
лексику задаёт пользователь (без неё шум съедает пользу), а правил согласования
всего два — расширенный набор в замере ронял точность.

## Что находит

* **`SPELL`** — слова, которых нет в языке, если на расстоянии одной правки
  есть словарное: «предложния» → «предложения», «уведомлеие» → «уведомление».
* **`AGREEMENT`**, правило `amod` — определение не согласовано с вершиной по
  падежу, числу или роду: «Указанная работы» → «Указанные работы».
* **`AGREEMENT`**, правило `case` — однопадежный предлог требует своего падежа:
  «согласно приказа» → «согласно приказу», «вопреки решения» → «вопреки
  решению».

## Что не находит

* **Пунктуацию.** Запятые не проверяются вообще.
* **Многопадежные предлоги** («в», «на», «с», «по», «за») — падеж зависит от
  смысла, и правило на них даёт ложные срабатывания.
* **Согласование сказуемого с подлежащим** — синтаксический разбор делового
  текста ошибается на этой дуге слишком часто.
* **Смысл, стиль, канцелярит, тавтологию** — это к другим инструментам.
* **Ошибки в словах короче 4 букв и в аббревиатурах** (`ПСД`, `ГОСТ`) —
  вариантов замены у них больше, чем пользы.
* **Ошибки на расстоянии двух и более правок** — «прдлжния» не будет исправлено.

Отдельное правило: слово рядом с инициалами не подчёркивается никогда —
«Ветровин А.Б.» и «А.Б. Ветровину». Фамилия несловарна по определению, а
держать фамилии в словаре значит хранить персональные данные в репозитории.

## Установка

```bash
uv add ruspell                    # только словарный слой
uv add "ruspell[agreement]"       # + слой согласования

pip install ruspell
pip install "ruspell[agreement]"

# из git, пока пакета нет на PyPI
uv add "ruspell[agreement] @ git+https://github.com/EZHOWWW/ruspell"
pip install "ruspell[agreement] @ git+https://github.com/EZHOWWW/ruspell"
```

Python 3.10+. Обязательные зависимости — `pymorphy3` и `pymorphy3-dicts-ru`,
больше ничего. Экстра `agreement` добавляет `slovnet`, `navec`, `razdel` и
`numpy`.

## Веса

Слою согласования нужны веса моделей, а ранжированию вариантов — частотный
словарь. В пакете их нет: скачиваются один раз.

```bash
ruspell-weights download              # в $RUSPELL_WEIGHTS_DIR или ~/.cache/ruspell
ruspell-weights download ./weights    # в конкретный каталог
ruspell-weights download-agreement    # без частотного словаря — 30 МБ вместо 58
python -m ruspell download            # то же самое, если скрипта нет в PATH
```

| Файл | Размер | Зачем | Лицензия |
|---|---|---|---|
| `navec_news_v1_1B_250K_300d_100q.tar` | 25 МБ | эмбеддинги для разбора | MIT, [natasha/navec](https://github.com/natasha/navec) |
| `slovnet_morph_news_v1.tar` | 2 МБ | морфология | MIT, [natasha/slovnet](https://github.com/natasha/slovnet) |
| `slovnet_syntax_news_v1.tar` | 3 МБ | синтаксис | MIT, [natasha/slovnet](https://github.com/natasha/slovnet) |
| `ru_full.txt` | 28 МБ | частоты слов для ранжирования вариантов | MIT, [hermitdave/FrequencyWords](https://github.com/hermitdave/FrequencyWords) |

Команда докачивает только недостающее, переживает временные отказы сети (шесть
попыток с удвоением паузы) и пишет через временный `.part`, так что оборванная
закачка не выглядит готовым файлом. Частотный словарь берётся из запиннного
коммита, а не из `master`: ветка — подвижная ссылка, и ранжирование поехало бы
без следа в истории. Запускать команду можно сколько угодно раз.

Каталог задаётся явно или переменной окружения:

```python
SpellChecker(weights_dir=Path("/opt/ruspell-weights"))
```

```bash
export RUSPELL_WEIGHTS_DIR=/opt/ruspell-weights
```

## Быстрый старт

```python
from ruspell import SpellChecker

checker = SpellChecker(vocabulary={"техрегламент", "энергоаудит"})
print(checker.layers)   # ('dictionary', 'agreement') — или только словарь, если весов нет

for issue in checker.check("Направляем предложния по существу вопроса."):
    print(issue.word, issue.start, issue.end, issue.category, issue.suggestions, issue.message)
# предложния 11 21 SPELL ('предложения',)

checker.correct("Уведомлеие и ещё раз уведомлеие.")
# 'Уведомление и ещё раз уведомление.'
```

```bash
uv run python examples/quickstart.py
```

## API

### `SpellChecker(vocabulary=(), *, weights_dir=None)`

Собирает слои один раз и держит их: словарь pymorphy3 и веса slovnet грузятся
секунды, а проверка текста — миллисекунды. **Один экземпляр на процесс.**
Экземпляр неизменяем и не хранит состояния между вызовами, поэтому его можно
звать из нескольких потоков.

| Параметр | Тип | Что делает |
|---|---|---|
| `vocabulary` | `Iterable[str]` | Доменная лексика: слова или фразы. Эти слова не считаются ошибкой. Одна строка вместо коллекции — `TypeError`. |
| `weights_dir` | `str \| Path \| None` | Где искать веса. По умолчанию `$RUSPELL_WEIGHTS_DIR`, иначе `~/.cache/ruspell`. |

| Метод / свойство | Возвращает | Что делает |
|---|---|---|
| `check(text)` | `list[Issue]` | Замечания к тексту. Повторы одной опечатки свёрнуты в одно замечание. |
| `correct(text)` | `str` | Текст с применённым первым вариантом каждого замечания. Повторы **не** свёрнуты: опечатка, встреченная трижды, исправляется трижды. |
| `layers` | `tuple[str, ...]` | Какие слои поднялись: `('dictionary',)` или `('dictionary', 'agreement')`. |
| `weights_dir` | `Path` | Каталог, в котором проверка искала веса. |

`check` и `correct` — разные действия, а не одна функция с флагом. Нужно и то и
другое — зовите оба.

### `Issue`

Замороженный `dataclass` без внешних зависимостей: библиотека не навязывает вам
ни pydantic, ни своей модели данных.

```python
@dataclass(frozen=True, slots=True)
class Issue:
    word: str                            # слово как оно написано в тексте
    start: int                           # text[issue.start : issue.end] == issue.word
    end: int
    category: IssueCategory              # "SPELL" | "AGREEMENT"
    suggestions: tuple[str, ...] = ()    # варианты замены, лучший первым
    message: str = ""                    # объяснение; у орфографии пустое
```

`issue.as_dict()` возвращает JSON-совместимый словарь (`IssueDict`) — для
HTTP-ответа или лога. Контекст вокруг ошибки берётся из самого текста срезом по
спану: библиотека не дублирует то, что у вас уже есть.

### Доменная лексика

| Функция | Что делает |
|---|---|
| `vocabulary_words(phrases)` | Разбирает строки на слова словаря: `["ФТП — Фондтехпроект"]` → `{"фтп", "фондтехпроект"}`. |
| `load_vocabulary(path)` | Читает JSON-файл со списком строк и разбирает его так же. |

### Веса

| Функция | Что делает |
|---|---|
| `default_weights_dir()` | `$RUSPELL_WEIGHTS_DIR` или `~/.cache/ruspell`. |
| `ruspell.weights.missing_weights(dir)` | Какие файлы весов отсутствуют — для health-check и `skipif` в тестах. |
| `ruspell.weights.download_weights(dir)` | То же, что консольная команда, но из кода. |
| `ruspell.weights.download_agreement_weights(dir)` | Только веса согласования, без частотного словаря. |

### Чистая логика

Вся логика — обычные функции без IO, импортируемые и тестируемые по отдельности:

```python
from ruspell.issues import (
    apply_issues,           # собрать исправленный текст по замечаниям
    collapse_repeats,       # свернуть повторы одной опечатки
    find_dictionary_issues, # найти несловарные слова (предикаты — параметры)
    merge_issues,           # слить слои, сняв пересечения по спану
    near_initials,          # слово рядом с инициалами — это ФИО
    shift,                  # перенести спан в координаты всего текста
)
from ruspell.dictionary import edits1, frequency_ranker, rank_suggestions
from ruspell.vocabulary import drop_vocabulary_words, in_vocabulary
from ruspell.agreement import find_disagreements, find_government_errors, inflect, match_case
from ruspell.check import build_layers, check_text
```

## Своя доменная лексика

Встроенного словаря в библиотеке нет — доменная лексика у каждого своя, а чужая
только мешает. Пустой словарь — рабочее состояние: проверка находит то же самое,
просто шумит на ваших терминах.

**Множеством слов:**

```python
SpellChecker(vocabulary={"техрегламент", "теплоузел", "оквэд"})
```

**Фразами — аббревиатура вместе с расшифровкой.** Из строки берутся все слова,
поэтому не будет подчёркнуто ни сокращение, ни расшифровка:

```python
SpellChecker(vocabulary=[
    "ФТП — Фондтехпроект",
    "ПСД — проектно-сметная документация",
])
```

Это же и способ подключить справочник, который ведут в вашей системе: список
строк из базы отдаётся как есть.

**Из файла:**

```python
from pathlib import Path

from ruspell import SpellChecker, load_vocabulary

SpellChecker(vocabulary=load_vocabulary(Path("vocabulary.json")))
```

Формат — JSON-список строк; образец с вымышленными терминами лежит в
[`examples/vocabulary.json`](examples/vocabulary.json).

**Составные слова** разбирать отдельно не нужно: словом считается
последовательность кириллических букв, поэтому и текст, и словарь режутся по
дефису одинаково. Строку `"машино-мест"` достаточно положить в словарь один
раз — она станет словами «машино» и «мест», ровно теми же, на которые
распадётся «машино-мест» в письме.

**Собрать словарь из своего корпуса** — рецепт в
[`examples/build_vocabulary.py`](examples/build_vocabulary.py): слова,
встреченные минимум в трёх *разных* документах и неизвестные pymorphy3.

> ⚠️ В такой словарь попадают фамилии: подписант повторяется из документа в
> документ и проходит любой частотный фильтр. **Персональным данным в словаре
> не место** — он уезжает в репозиторий, в образ и в чужие руки. Скрипт
> перечисляет кандидатов, похожих на ФИО, но решение оставляет человеку:
> автоматический фильтр выбрасывает термины и всё равно пропускает половину
> фамилий. Проверке фамилии не нужны — за них отвечает правило «слово рядом с
> инициалами».

## Встраивание в свой проект

Библиотека ничего не знает про HTTP, и это осознанно: обёртка над `check` — три
строки, а зависимость от веб-фреймворка в проверке текста не нужна никому.

```python
# app.py — FastAPI здесь только как пример; сама библиотека от него не зависит
from functools import lru_cache

from fastapi import Depends, FastAPI
from pydantic import BaseModel

from ruspell import SpellChecker

app = FastAPI()


@lru_cache(maxsize=1)
def get_checker() -> SpellChecker:
    return SpellChecker(vocabulary=load_my_vocabulary())


class CheckRequest(BaseModel):
    text: str


@app.post("/check")
def check(request: CheckRequest, checker: SpellChecker = Depends(get_checker)) -> dict:
    return {"issues": [issue.as_dict() for issue in checker.check(request.text)]}


@app.get("/health/spelling")
def spelling_health(checker: SpellChecker = Depends(get_checker)) -> dict:
    return {"layers": checker.layers, "weights_dir": str(checker.weights_dir)}
```

Практические замечания:

* **Собирайте `SpellChecker` на старте, а не в обработчике** — первый вызов
  грузит словарь и веса (около двух секунд), остальные считают миллисекунды.
* **Не создавайте по экземпляру на запрос**: каждый займёт свои сотни мегабайт.
* **Проверка синхронная и считает на CPU.** В async-приложении зовите её через
  `asyncio.to_thread` / `run_in_threadpool`, если тексты большие.
* **Отдавайте наружу `as_dict()`**, а не сам `Issue`: тогда контракт вашего API
  не зависит от версии библиотеки.
* **Режьте документ на строки сами**: границей предложения проверка считает
  перевод строки.

## Поведение без весов

Слой согласования опционален, и его отсутствие — **не ошибка**, а
документированный режим:

| Ситуация | Что происходит |
|---|---|
| экстра `agreement` не установлена | `layers == ('dictionary',)`, в лог `ruspell` — warning |
| веса не скачаны или каталог не тот | то же самое |
| архив весов обрезан или несовместим | то же самое |
| разбор упал на конкретной строке | строка проверяется словарём, warning в лог, остальной текст не страдает |
| нет частотного словаря `ru_full.txt` | варианты ранжируются эвристикой по форме слова |
| `ru_full.txt` оборван при закачке | то же самое, warning в лог: обрывок не притворяется словарём |

`check` и `correct` работают всегда. Какие слои поднялись — видно в
`checker.layers`, причина — в логе:

```python
import logging

logging.basicConfig(level=logging.WARNING)
# WARNING:ruspell:Слой согласования не поднялся (Не найдены веса slovnet в
# /home/user/.cache/ruspell: ...) — работает только словарь
```

Без частотного словаря ранжирование заметно хуже: для «предложния» эвристика
предпочтёт «предложная» (та же длина, те же крайние буквы), а частоты — верное
«предложения». Если вам важен `correct`, качайте `ru_full.txt`.

## Производительность и память

Замеры на обычном ноутбуке:

| | Время | Память процесса |
|---|---|---|
| сборка `SpellChecker` без весов | ~1 с | ~90 МБ (словарь pymorphy3) |
| сборка `SpellChecker` с весами | ~2 с | ~430 МБ (+200 МБ slovnet, +150 МБ частоты) |
| `check` одного предложения | 10–15 мс | — |
| `check` без слоя согласования | <1 мс | — |

Память — главная цена слоя согласования. Если 400 МБ на процесс дорого: не
ставьте экстру `agreement` (останется словарный слой) или не качайте
`ru_full.txt` (сэкономит 150 МБ ценой худшего ранжирования).

## Ограничения

* **Пунктуация не проверяется.** Совсем.
* **Синтаксический разбор ошибается.** Поэтому проверяются только два правила,
  на которых он надёжен, а не всё, что теоретически можно проверить:
  расширенный набор правил в замере ронял точность.
* **Границей предложения считается перевод строки.** Абзац из пяти предложений
  разбирается как одно, и качество разбора падает. Режьте текст сами, если это
  важно.
* **Одно замечание на слово.** При пересечении спанов выигрывает более ранний
  слой (словарный): на одном слове не должно быть двух объяснений.
* **`correct` применяет первый вариант вслепую.** Это годится для черновика, но
  не заменяет человека: показывайте пользователю `check`, а `correct`
  используйте там, где правку потом смотрят глазами.
* **Только кириллица.** Латиница, цифры и смешанные токены игнорируются.
* **Модели натренированы на новостях** (`*_news_v1`): на разговорном тексте и
  на узкой терминологии разбор хуже.
